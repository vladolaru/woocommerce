# B3ai Native WooPay Frontend Assets Parity Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use $subagent-driven-development (recommended) or $executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Restore the shopper-visible WooPay checkout frontend surfaces in Core-owned native WooPayments using normal WooCommerce Core asset/build workflows.

**Architecture:** Extend the existing native WooPayments checkout bridge and WooPay session service/controller so Core exposes the reference WooPay config globals, save-my-info metadata/session behavior, express button placeholders, and frontend script data without depending on the standalone WooPayments plugin runtime. Keep Core assets in the existing classic and Blocks asset systems: classic code under `client/legacy/js/frontend`, Blocks code under `client/blocks/assets/js/extensions/payment-methods/woopayments`, and built artifacts generated by `@woocommerce/classic-assets` plus Blocks webpack.

**Tech Stack:** WooCommerce Core PHP services/controllers, WooCommerce sessions and checkout hooks, WooCommerce Blocks payment method integration, React/JS frontend assets, Grunt classic asset build, Blocks webpack build, PHPUnit, Jest, wp-env, browser automation, restored cross-store harness.
